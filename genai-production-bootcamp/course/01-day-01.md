# DAY 1 — Shot Grammar and the Control Ladder

**TIME BUDGET: 5h** — 0h watch · 0.5h read · 4h do · 0.5h QC/log

## OUTCOME
By end of day you have: a shot log of a real film sequence with the 180° line identified; a
working project repo; and **the rung 0 vs rung 2 comparison** — the single most useful artifact
in the whole course for explaining what you do.

## WHY THIS MATTERS
Every employer in the market research asks for the same thing in different words: repeatable,
structured output. Today you learn the difference between *finding* a shot and *specifying* one.
Everything for the next 20 days is downstream of this. It is also the thing that separates you
from the enormous pool of people who can prompt.

## LEARN
- Shot sizes: EWS / WS / MS / MCU / CU / ECU / insert
- Lens logic: 24 / 50 / 85 and what each one *means*
- The 180° line, screen direction, eyeline
- The **control ladder**: rungs 0→6 and what each rung removes from chance
- What stays stochastic no matter what you do

## WATCH
**None today.** Deliberately. Day 1 is reps, not video.
> **Do Day 0 first if you haven't:** run `bash tools/audit-tutorials.sh` (60–90 min) so the rest
> of the course's videos are scored before you need them.

## READ
- `modules/storyboarding.md` §1 (shot grammar) — 20 min
- `modules/higgsfield.md` §2–§4 (live capability map, routing, control ladder) — 20 min

## DO
1. **(45 min) Grammar audit — exercise S1.** Pick a 60-second sequence from a film you admire.
   Log every shot: size, estimated focal length, move, screen direction. Draw the 180° line on
   a floor-plan sketch.
2. **(30 min) Project setup.** Create the repo structure from `modules/higgsfield.md` §5.
   `git init`. Add a `.gitignore` that excludes media directories but keeps JSON and CSV.
3. **(90 min) Exercise H2 — the control ladder ablation.** One shot idea. Generate it four times:
   - **Rung 0:** text prompt only
   - **Rung 1:** + a start frame you generated deliberately
   - **Rung 2:** + an end frame
   - **Rung 4:** + an `image_reference` for the subject
   Use `seedance_2_0_mini` or `mode: "fast"` at 480p, `generate_audio: false`. Same intent
   every time. Change *only* the control inputs.
4. **(45 min) Exercise H1 — router literacy.** Ten shot descriptions; name the model and the
   *constraint* that drove the choice. Check against `modules/higgsfield.md` §3.
5. **(30 min)** Build the 4-up comparison in any tool and write one sentence per rung: *what
   stopped varying*.

## VERIFY
- [ ] Shot log has ≥8 rows with the 180° line correctly drawn
- [ ] Four generations exist, differing **only** in control inputs
- [ ] You can state, per rung, exactly what stopped varying
- [ ] H1 scored ≥8/10
- [ ] Repo committed

## SHIP
`day01/shot_log.md`, `day01/ladder_comparison.mp4` (4-up), `day01/ladder_notes.md`.
**Keep the comparison forever — it goes in your portfolio breakdown and you will show it in
interviews.**

## FAILURE CONDITIONS
- **All four generations look similar** → your prompt was already doing the work of a start
  frame, or your subject is too generic. Pick something with a distinctive silhouette.
- **Rung 2 looks *worse*** → your end frame is incompatible with your start frame (different
  scale, lighting or angle). The model is being asked for an impossible interpolation.
- **You spent 3 hours on rung 0 trying to get a good shot** → that is exactly the habit this
  day exists to break. Move on.

## RECOVERY
If generations fail entirely: check `models_explore` for the current model id — ids change.
If the end frame fights the start frame: regenerate the end frame *from* the start frame using
`nano_banana_2` img2img rather than generating it independently.

## STOP RULE
Stop when you can look at any generated clip and name which rung produced it, and when you have
written the four sentences. **Not** when the shots look good — they will not, and that is fine.
