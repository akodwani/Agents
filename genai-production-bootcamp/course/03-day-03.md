# DAY 3 — Start/End Frame Bracketing + Console v1

**TIME BUDGET: 5h** — 0h watch · 0.5h read · 4h do (incl. 1h Tool Track) · 0.5h QC

## OUTCOME
You can reliably bracket a shot between two authored frames, and you have the `ShotSpec` schema
running in SQLite holding real data.

## WHY THIS MATTERS
Bracketing is the core anti-variance technique of the entire course, and it is portable — the
live catalog shows `start_image`/`end_image` on ten different models across five vendors. Learn
it once, use it regardless of which model wins next quarter.

## LEARN
- Deriving an end frame *from* a start frame (not independently)
- Why incompatible brackets produce worse output than no bracket
- `ShotSpec` as structured creative intent
- Reference hashing — what "locked" actually means mechanically

## WATCH
**None.** This is a reps day.

## READ
- `modules/ai-development.md` §3 (Pydantic / ShotSpec) — 15 min
- `modules/higgsfield.md` §4 (control ladder, iteration counts, abandonment) — 15 min

## DO
1. **(60 min) TOOL TRACK — Console v1.** Implement the `ShotSpec` Pydantic model and the SQLite
   schema from `projects/shot-control-console.md`. Build `console add` and `console list`.
   **Then immediately use it** — enter the shot spec for tomorrow's work.
2. **(90 min) Bracket drill.** Three different shots. For each:
   - Author a start frame deliberately (Nano Banana Pro, or Cinema Studio Image 2.5)
   - Derive the end frame **from the start frame** via img2img / `nano_banana_2` inpaint —
     same subject, same lighting, changed position or state
   - Generate at rung 2, 480p fast tier
3. **(60 min) Failure study.** Deliberately build one *incompatible* bracket (end frame from a
   different angle or lighting). Generate it. **Write down what the model did.** Understanding
   this failure mode saves you days later.
4. **(30 min)** Store all four generations' metadata in the Console. Hash the reference frames.

## VERIFY
- [ ] `console add` / `console list` work; 4+ real specs stored
- [ ] Three compatible-bracket shots generated at rung 2
- [ ] You can state the rule for what makes two frames a *compatible* bracket
- [ ] The incompatible bracket's failure is documented in your own words
- [ ] Reference hashes stored

## SHIP
`console/` (v1, committed), `day03/brackets/` (4 clips + sidecars), `day03/bracket_rules.md`.

## FAILURE CONDITIONS
- **Model ignores the end frame** → confirm the model actually exposes an `end_image` role.
  Not all do — `veo3_1` and `kling3_0_turbo` accept only `start_image`. Check `models_explore`.
- **Output morphs unpleasantly between frames** → the two frames are too far apart. Either move
  the end frame closer to the start, or accept a shorter duration.
- **Console eats 3 hours** → stop at the hour. It is a 1-hour block by design. The CLI only
  needs `add` and `list` today; everything else comes later.

## RECOVERY
If bracketing consistently underperforms: your start frames are probably weak. A bracket cannot
rescue a poorly composed start frame — it faithfully interpolates between two mediocre images.
Go back and spend the time on the frame.

## STOP RULE
Stop when you can predict, before generating, whether a bracket will work. That predictive
ability — not the clips — is the deliverable.
