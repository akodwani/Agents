# DAY 9 — ComfyUI Workflow B + Console v2

**TIME BUDGET: 5h** — 0.5h watch · 0.5h read · 3.5h do (incl. 1h Tool Track) · 0.5h QC

## OUTCOME
**`reference_pose_to_hero_frame.json`** — a working, exported, version-controlled ComfyUI
workflow. Plus Console prompt-variant generation.

## WHY THIS MATTERS
The workflow JSON *is* the portfolio artifact. "I built a controlled ComfyUI workflow, here is
the JSON, here is the README, here is a strength sweep showing where control breaks down" is
precisely what the ComfyUI-requiring listings are asking for. A screenshot of someone else's
workflow is not.

## LEARN
- IPAdapter / reference conditioning for identity
- ControlNet for pose and edge
- LoRA loading and weighting (**using**, not training)
- Workflow JSON as a versioned artifact
- Prompt templating from structured data

## WATCH
Your audited ComfyUI **SECONDARY** (likely `-ZyGkd0uRk8`, Flux ControlNet), ~25 min —
**ControlNet wiring chapters only.**
⚠️ **Verify it uses a FLUX-trained ControlNet.** SD1.5/SDXL ControlNets are incompatible with
FLUX checkpoints and the failure is *silent* — the control image is simply ignored.

## READ
- `modules/comfyui.md` §3 (Workflow B) and §4 (reproducibility discipline) — 20 min

## DO
1. **(60 min) TOOL TRACK — Console v2.** Build `console prompt` (template-based prompt variants
   from a `ShotSpec`) and `console manifest` (JSON + CSV export). **Use it immediately** to
   generate prompts for today's Comfy work.
2. **(150 min) EXERCISE C4 — build Workflow B.**
   ```
   locked character ref ──→ IPAdapter/reference encoder ─┐
   pose or line-art     ──→ ControlNet (Pose/Canny)      ─┤
   checkpoint + CLIP (+/-)                                ├─→ KSampler (SEED FIXED)
   [optional] LoRA (0.5–0.8)                              ┘        ↓
                                                       VAE Decode → Upscale → Save
   ```
   Target: **your Day 2 locked character, rendered in a pose you specify.**
3. **(30 min)** Export the JSON to `workflows/B_ref_pose_hero_v1.json`. Write the accompanying
   README: inputs, required models, runtime, credit cost, the three parameters worth touching.
   Commit both.
4. **(30 min)** Feed the resulting hero frame to Higgsfield as a `start_image` and generate a
   4-second shot. **This handoff is the spine of the whole pipeline — prove it works today.**

## VERIFY
- [ ] The generated character is recognisably your locked character
- [ ] The pose matches your control input
- [ ] Seed is fixed; re-running gives the same frame
- [ ] Workflow JSON exported, README written, both committed
- [ ] The Comfy → Higgsfield handoff produced a usable shot
- [ ] `console prompt` produced the prompts you actually used

## SHIP
`workflows/B_ref_pose_hero_v1.json` + README, `day09/hero_frame.png`, `day09/handoff_test.mp4`,
Console v2 committed.

## FAILURE CONDITIONS
- **Character not recognisable** → IPAdapter weight too low, or your reference is too subtle.
  Raise the weight; prefer a subject with distinctive high-contrast features.
- **Pose ignored entirely** → **the FLUX/ControlNet architecture mismatch.** Check this first,
  every time. It is silent, not an error.
- **Everything is muddy** → CFG too high with a modern checkpoint. Try 3.5.
- **Console block runs long** → stop at 60 minutes. `prompt` and `manifest` only.

## RECOVERY
If ControlNet is genuinely not available for your checkpoint on Cloud, switch checkpoints rather
than abandoning control. A less-preferred checkpoint with working control beats a preferred one
without it — control is the point of the exercise.

## STOP RULE
Stop when the JSON is exported and the handoff test works. A workflow you cannot re-run tomorrow
is not a workflow.
