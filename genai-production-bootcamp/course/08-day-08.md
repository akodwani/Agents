# DAY 8 — ComfyUI on Comfy Cloud

**TIME BUDGET: 5h** — 1.5h watch · 0.5h read · 2.5h do · 0.5h QC

## OUTCOME
Graph literacy, seed determinism proven to yourself, and Comfy Cloud running.

## WHY THIS MATTERS
**This is your single highest-leverage gap.** ComfyUI is a hard requirement in roughly two-thirds
of the serious listings in the market sample. It is the specific thing that separates "prompts
things" from "builds workflows" in every job description that draws the line. Two days here
changes which jobs you can apply to.

## LEARN
- Node graphs; tracing a tensor from load → sample → decode → save
- Checkpoints, CLIP conditioning, VAE, latent space
- **Seeds and determinism — the foundation of reproducibility**
- Samplers/schedulers/steps/CFG at practical ranges only
- img2img and denoise strength (the most useful dial you own)

## ⚠️ SETUP NOTE — read before you start
Comfy Cloud free tier gives **400 credits/month, no card**, which is enough for today and
tomorrow's *learning*. But **the Cloud API requires an active paid subscription** ($20/mo
Standard). If you intend the Day 21 Console to make a real API call, start the subscription
**today** so billing and access are settled before you need them.
Also note: **30-minute max workflow runtime** on Standard/Creator, and a **serial queue** —
one prompt at a time. Design workflows accordingly.

## WATCH
Your audited **ComfyUI PRIMARY** (likely `-igiHGaxKek`), ~60 min.
⚠️ If it is a **local-install** tutorial, **skip the entire setup section** — it is unusable on
6 GB VRAM and irrelevant on Cloud. Jump to the node-graph chapters.
Plus ~20 min of the ControlNet chapters.

## READ
- `modules/comfyui.md` §1–§2 — 25 min. **Read the FLUX/ControlNet compatibility rule twice.**

## DO
1. **(30 min)** Comfy Cloud set up. Load the default text-to-image workflow. Do not generate yet.
2. **(45 min) EXERCISE C1 — graph literacy.** Write down every node, its inputs, and what it
   hands to the next. Trace the path from checkpoint to saved pixel with no gaps.
3. **(30 min) EXERCISE C2 — seed determinism.** Fix a seed. Run twice — confirm identical output.
   Change only the seed, run again. **Screenshot this.** It is the foundation of every
   reproducibility claim you will make.
4. **(45 min) Parameter sweep.** Change ONE variable at a time and log the effect: steps
   (15/25/40), CFG (2/5/9), sampler (2 different ones). Build a labelled contact sheet.
5. **(30 min) img2img + denoise sweep.** Same input image at denoise 0.2 / 0.5 / 0.8. Understand
   the dial.

## FAILURE CONDITIONS
- **Output changes when it shouldn't** → seed is randomised somewhere. Find it before debugging
  anything else. This is the #1 time sink for beginners.
- **Output identical when it shouldn't be** → you edited a node not actually wired into the
  graph. Trace the wire.
- **A node is missing on Cloud** → custom-node support is a *curated* set, not all of GitHub.
  Find a supported equivalent rather than fighting it.
- **Job cancelled** → you exceeded the 30-minute cap. Split the workflow.

## RECOVERY
If the interface is overwhelming: ignore everything except the six nodes in the default graph.
You do not need to understand the node library. You need to understand one path through it.

## STOP RULE
Stop when you can predict what a parameter change will do *before* you run it, and when
determinism is proven. Not when your images look good — that is tomorrow's problem.
